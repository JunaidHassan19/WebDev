================================================================================
                          SCOPE IN JAVASCRIPT
================================================================================

WHAT IS SCOPE?
--------------
Scope refers to the region of the code where a variable or function is accessible.
In other words, scope determines where a variable can be used or accessed.
Every variable has a scope - it can be accessed only within that scope.

Think of scope as a boundary around a variable - it can only be used within
that boundary. If you try to use a variable outside its scope, you'll get an error.


================================================================================
                         TYPES OF SCOPE IN JAVASCRIPT
================================================================================

JavaScript has several types of scope:
1. Global Scope
2. Function Scope (Local Scope)
3. Block Scope
4. Lexical Scope


================================================================================
1. GLOBAL SCOPE
================================================================================

DEFINITION:
-----------
A variable declared in global scope is accessible from anywhere in your code.
Global scope is the outermost scope - variables here are available to all functions
and blocks.

HOW TO CREATE:
--------------
Variables declared outside any function or block are in global scope.

EXAMPLE:
--------

// This is global scope
var globalVar = "I am global";
let globalLet = "I am also global";
const globalConst = "I am global too";

function myFunction() {
    console.log(globalVar);   // Output: I am global (accessible here)
}

if (true) {
    console.log(globalVar);   // Output: I am global (accessible here too)
}

myFunction();


BROWSER GLOBAL SCOPE:
---------------------
In a browser, global variables become properties of the 'window' object.

Example:
var name = "John";
console.log(window.name);  // Output: John (var creates a window property)

Note: 'let' and 'const' do NOT create window properties


GLOBAL SCOPE ISSUES:
--------------------
Global variables should be used sparingly because:
- They can be accidentally modified from anywhere
- They pollute the global namespace
- They can cause naming conflicts
- They make code harder to debug

Example of a problem:
var count = 0;

function increment() {
    count++;  // Modifying global variable
}

function reset() {
    count = 0;  // Also modifying the same variable
}

increment();
reset();  // Hard to track what changed 'count'


================================================================================
2. FUNCTION SCOPE (LOCAL SCOPE)
================================================================================

DEFINITION:
-----------
Variables declared inside a function are only accessible within that function.
This is called function scope or local scope.
Each function creates its own scope.

HOW TO CREATE:
--------------
Variables declared inside a function using var, let, or const are in function scope.

EXAMPLE:
--------

function greeting() {
    var message = "Hello";  // Function scope
    console.log(message);   // Output: Hello (accessible here)
}

greeting();
console.log(message);  // Error: message is not defined (not accessible here)


ACCESSING GLOBAL FROM FUNCTION:
--------------------------------
A function can access both global and local variables.

Example:
var globalMessage = "Hi from global";

function myFunc() {
    var localMessage = "Hi from function";
    console.log(globalMessage);   // Works (can access global)
    console.log(localMessage);    // Works (can access local)
}

myFunc();
console.log(globalMessage);   // Works
console.log(localMessage);    // Error: localMessage is not defined


EACH FUNCTION HAS ITS OWN SCOPE:
---------------------------------
Each function creates a separate scope. Variables in one function
cannot be accessed by another function.

Example:
function func1() {
    var x = 10;
    console.log(x);  // Output: 10
}

function func2() {
    console.log(x);  // Error: x is not defined (different scope)
}

func1();
func2();


FUNCTION PARAMETERS ARE LOCAL:
-------------------------------
Function parameters are treated as local variables within the function.

Example:
function add(a, b) {
    var result = a + b;
    return result;
}

console.log(a);  // Error: a is not defined (it's local to the function)


NESTED FUNCTIONS:
-----------------
A function inside another function can access both its own scope
and the outer function's scope.

Example:
function outer() {
    var outerVar = "I'm outside";
    
    function inner() {
        var innerVar = "I'm inside";
        console.log(innerVar);   // Output: I'm inside
        console.log(outerVar);   // Output: I'm outside (can access outer)
    }
    
    inner();
    console.log(innerVar);  // Error: innerVar is not defined (not in outer scope)
}

outer();


================================================================================
3. BLOCK SCOPE
================================================================================

DEFINITION:
-----------
Block scope refers to variables being accessible only within a code block.
A block is any code enclosed in curly braces: { }
Block scope applies to variables declared with 'let' and 'const'.
Variables declared with 'var' do NOT have block scope.

CODE BLOCKS INCLUDE:
- if/else statements
- for loops
- while loops
- switch statements
- try/catch blocks
- function bodies (functions also create their own scope)

EXAMPLE WITH LET:
-----------------

if (true) {
    let x = 10;
    console.log(x);  // Output: 10 (accessible inside block)
}

console.log(x);  // Error: x is not defined (not accessible outside block)


EXAMPLE WITH CONST:
-------------------

for (let i = 0; i < 3; i++) {
    const message = "Hello";
    console.log(message);  // Works (each iteration has its own message)
}

console.log(message);  // Error: message is not defined


VAR DOES NOT HAVE BLOCK SCOPE:
-------------------------------
Variables declared with 'var' leak out of blocks! This is called "hoisting"
and is considered bad practice.

Example:
if (true) {
    var y = 20;
    console.log(y);  // Output: 20
}

console.log(y);  // Output: 20 (accessible! var ignores block scope)


This is why 'let' and 'const' are preferred over 'var'.


IF/ELSE BLOCK SCOPE:
---------------------

if (true) {
    let blockVar = "Inside block";
    console.log(blockVar);  // Output: Inside block
}

console.log(blockVar);  // Error: blockVar is not defined


FOR LOOP BLOCK SCOPE:
---------------------

for (let i = 0; i < 3; i++) {
    console.log(i);  // Works (i is in block scope)
}

console.log(i);  // Error: i is not defined (outside block scope)


WITH VAR (Bad Example):
for (var i = 0; i < 3; i++) {
    console.log(i);
}

console.log(i);  // Output: 3 (var leaks out of loop!)


NESTED BLOCKS:
--------------

{
    let outer = "Outer block";
    {
        let inner = "Inner block";
        console.log(outer);  // Works (can access outer block)
        console.log(inner);  // Works
    }
    console.log(inner);  // Error: inner is not defined
}


================================================================================
4. LEXICAL SCOPE
================================================================================

DEFINITION:
-----------
Lexical scope (also called static scope) means that the scope of a variable
is determined by its position in the source code.
A function's scope is determined by where it's defined in the code,
NOT where it's called from.

In other words: Inner functions can access outer functions' variables
because of where they are written in the code, regardless of where
the function is called.

This creates a SCOPE CHAIN - JavaScript looks for variables first in
the current scope, then in the outer scope, and so on up to global scope.


SIMPLE EXAMPLE:
---------------

var globalVar = "Global";

function outer() {
    var outerVar = "Outer";
    
    function inner() {
        var innerVar = "Inner";
        console.log(innerVar);    // Output: Inner (own scope)
        console.log(outerVar);    // Output: Outer (outer scope)
        console.log(globalVar);   // Output: Global (global scope)
    }
    
    inner();
}

outer();


SCOPE CHAIN EXPLANATION:
------------------------

When JavaScript looks for a variable, it searches in this order:
1. Current scope (local variables)
2. Parent function scope (outer function)
3. Grandparent function scope
... and so on ...
n. Global scope

If not found anywhere, you get a ReferenceError.


EXAMPLE OF SCOPE CHAIN:
-----------------------

var x = 1;

function level1() {
    var x = 2;
    
    function level2() {
        var x = 3;
        
        function level3() {
            console.log(x);  // Output: 3
            // Finds x in level3's scope
        }
        
        level3();
    }
    
    level2();
}

level1();


VARIABLE SHADOWING:
-------------------
When you declare a variable with the same name in an inner scope,
it "shadows" (hides) the outer variable.

Example:
var name = "Global";

function outer() {
    var name = "Outer";
    console.log(name);  // Output: Outer (uses outer's name, not global)
}

outer();
console.log(name);  // Output: Global


CLOSURES (Lexical Scope in Action):
------------------------------------

function createCounter() {
    let count = 0;  // This variable is "enclosed" in the function
    
    function increment() {
        count++;
        console.log(count);
    }
    
    return increment;
}

const counter = createCounter();
counter();  // Output: 1
counter();  // Output: 2
counter();  // Output: 3

The inner 'increment' function remembers the 'count' variable
from its lexical scope (where it was defined).


IMPORTANT RULE:
---------------
Where a function is DEFINED determines what variables it can access.
Where a function is CALLED does NOT affect its scope.

Example:
var x = "Global";

function inner() {
    console.log(x);
}

function outer() {
    var x = "Outer";
    inner();  // Calling inner here
}

outer();  // Output: Global
// Even though inner() is called inside outer(),
// it still accesses the global x, not outer's x


================================================================================
COMPARISON TABLE
================================================================================

Scope Type      | Created By              | Accessible Where                | Hoisted?
----------------|------------------------|---------------------------------|---------
Global          | Variables outside      | Anywhere in code                | var: yes
                | functions              |                                 | let/const: no

Function        | Variables inside       | Only within that function       | var: yes
                | functions              |                                 | let/const: no

Block           | let/const in {}        | Only within that block          | let/const: No
                |                        | (NOT var)                       | var: No (ignored)

Lexical         | Inner function         | Determined by where code        | N/A
                | accesses outer scope   | is written                      |


================================================================================
BEST PRACTICES
================================================================================

1. MINIMIZE GLOBAL VARIABLES
   - Use local variables whenever possible
   - Avoid polluting the global namespace

2. USE LET AND CONST INSTEAD OF VAR
   - let and const have block scope (var does not)
   - This prevents accidental variable leaks

3. UNDERSTAND LEXICAL SCOPE
   - Remember: scope is determined where code is written, not where it's called
   - This enables powerful patterns like closures

4. AVOID VARIABLE SHADOWING
   - Don't use the same variable names in nested scopes
   - It makes code confusing and hard to debug

5. USE CONSISTENT NAMING
   - Make it clear where variables come from
   - Use meaningful names

6. KEEP SCOPE AS NARROW AS POSSIBLE
   - Declare variables where they're needed
   - This makes code easier to understand and maintain


================================================================================
SUMMARY
================================================================================

GLOBAL SCOPE
- Variables accessible everywhere
- Avoid using too many

FUNCTION SCOPE
- Variables only accessible within the function
- Each function has its own scope
- Nested functions can access outer function variables

BLOCK SCOPE
- Variables declared with let/const only in that block
- var ignores block scope
- Created by if, for, while, {}, etc.

LEXICAL SCOPE
- Scope determined where code is written
- Inner functions can access outer function variables
- Creates a scope chain for variable lookup


Understanding scope is crucial for writing clean, bug-free JavaScript code!
