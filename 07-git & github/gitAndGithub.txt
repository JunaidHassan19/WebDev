Git and GitHub

Git is a version control system used to track changes in files over time. It helps developers save versions of their code, collaborate with others, and go back to earlier states if needed.

GitHub is a cloud-based platform that hosts Git repositories online. It makes it easy to share code, collaborate with teams, and manage projects remotely.

Key differences:
- Git = local version control tool
- GitHub = online hosting and collaboration platform

Why Git is important:
- Tracks code changes
- Helps work in teams
- Makes collaboration easier
- Prevents losing work
- Lets you revert mistakes

Basic Git terms:

1. Repository (repo)
   - A project folder tracked by Git.

2. Commit
   - A saved version of the project.

3. Branch
   - A separate line of development.

4. Merge
   - Combining changes from one branch into another.

5. Clone
   - Downloading a repository from GitHub to your local computer.

6. Pull
   - Getting the latest changes from a remote repository.

7. Push
   - Sending your local commits to GitHub.

8. Remote
   - The online version of your repository on GitHub.

9. Working Directory
   - Your current local project folder.

10. Staging Area
   - Files ready to be committed.

11. Fork
   - Your own copy of someone else's GitHub repository.

Configuring Git

Before using Git, configure your identity:

git config --global user.name "Your Name"
git config --global user.email "you@example.com"

git config --global --list

This tells Git who is making the commits.

Basic Git commands:

1. git init
   - Initialize a new Git repository in the current folder.

2. git status
   - Check the status of files in the project.

3. git add <file>
   - Add a specific file to the staging area.

4. git add .
   - Add all changed files to the staging area.

5. git commit -m "message"
   - Save changes with a commit message.

6. git log
   - View the commit history.

7. git branch
   - Show all branches in the project.

8. git checkout -b branchName
   - Create and switch to a new branch.

9. git checkout branchName
   - Switch to an existing branch.

10. git merge branchName
   - Merge a branch into the current branch.

11. git clone <repo-url>
   - Clone a repository from GitHub.

12. git pull origin main
   - Pull the latest changes from the main branch.

13. git push origin main
   - Push local changes to the GitHub main branch.

14. git remote -v
   - View remote repository URLs.

Clone command

To download an existing GitHub project on your computer:

git clone https://github.com/username/repository.git
cd repository

This creates a local copy of the repository.

Status command

Use git status to see:
- modified files
- untracked files
- files staged for commit
- branch you are currently on

Example:

git status

Add and push commands

To stage files:

git add fileName.html
git add .

To save changes with a commit message:

git commit -m "Add homepage design"

To upload to GitHub:

git push origin main

Push command

The push command sends your local commits to the remote repository:

git push origin main

If the branch is new, you may use:

git push -u origin main

The -u flag sets the upstream tracking branch for future pushes.

Init command

To start a new Git repository in a folder:

git init

Then add files:

git add .
git commit -m "Initial commit"

Push local repository to GitHub

If you have a project created locally and want to upload it to GitHub:

git init
git add .
git commit -m "Initial project setup"
git branch -M main
git remote add origin https://github.com/yourusername/repo.git
git push -u origin main

This is the standard process for pushing a local repo to a remote GitHub repository.

GitHub workflow

A common development workflow:

1. Create a repository on GitHub.
2. Clone it to your local machine.
3. Make changes in your project files.
4. Check git status.
5. Add files using git add .
6. Commit with git commit -m "message"
7. Pull latest changes before pushing if needed.
8. Push to GitHub using git push origin main
9. Open a Pull Request if working with a team.

Example workflow:

git clone https://github.com/username/repository.git
cd repository
git status
git add .
git commit -m "Update layout"
git pull origin main
git push origin main

Git branches

Branches let you work on different features or fixes without affecting the main project.

Common branch commands:

git branch

git checkout -b feature/homepage

or

git switch -c feature/homepage

To switch branches:

git checkout main

git checkout feature/homepage

To delete a branch:

git branch -d feature/homepage

Branching is useful when multiple people work on the same project.

Merging branches

When a feature is complete, merge it back into the main branch:

git checkout main
git merge feature/homepage

This combines the changes from the feature branch into the main branch.

If there are no conflicting edits, Git merges automatically.

Pull command

The pull command gets the newest changes from the remote repository:

git pull origin main

It is useful before pushing to avoid conflicts and keep your local repo updated.

Merge conflicts

A merge conflict happens when two people edit the same line in the same file, or when Git cannot decide which version to keep.

Example:

git pull origin main

If conflicts appear, Git marks the problem areas in the file.

You must resolve them manually by editing the file and deciding the final correct code.

After fixing the conflict:

git add <file>
git commit -m "Resolve merge conflict"

Fixing mistakes

Git provides commands to undo mistakes:

1. Undo a change in a file:
   git restore <file>

2. Discard all working tree changes:
   git restore .

3. Undo the last commit but keep changes:
   git reset --soft HEAD~1

4. Undo the last commit and remove changes:
   git reset --hard HEAD~1

5. Check previous version of a file:
   git log
   git checkout <commit-id> -- <file>

Always be careful with reset --hard because it permanently removes the changes.

Fork

A fork is a personal copy of someone else's GitHub repository.

Why use a fork?
- You can make changes without affecting the original project.
- It is common in open-source development.

How to fork:
1. Go to the repository on GitHub.
2. Click Fork.
3. Clone your fork to your computer.

Example:

git clone https://github.com/yourusername/repository.git
cd repository

If you want to keep your fork updated with the original repository, add an upstream remote:

git remote add upstream https://github.com/originalowner/repository.git
git fetch upstream
git merge upstream/main

This helps you sync your fork with the original project.

Common GitHub features:

- Repositories
- Pull requests
- Issues
- Branches
- Forks
- Actions
- README files

Important notes:
- Git tracks your code history locally.
- GitHub stores your repository online and allows collaboration.
- Always commit meaningful messages.
- Use branches when working on features or fixes.
- Pull before pushing to avoid conflicts.
- Use forks when collaborating on other people's projects.

Summary:
Git helps developers track and manage project versions, while GitHub provides an online platform to host, share, and collaborate on those projects. Together, they are essential tools in modern software development.
